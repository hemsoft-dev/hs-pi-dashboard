Architecture evaluation

Architecture: 7.2/10. Confidence: Medium.

Application type: a private, read-only fleet dashboard for one operator. Agents on five tailnet machines expose session, usage, Herdr and project data over HTTP; one always-on server on Mini aggregates them every 5 seconds into an embedded HTML page viewed on desktop, in T3 Code's panel and on a phone. The agent also pushes T3 snapshots to project-manager's pmd. Scale is five machines; no availability target is declared.

Architecture criteria
CriterionRating (1 to 10)Evidence
Product and deployment fit8One static Go binary per platform with two modes and no runtime dependencies fits a five-machine tailnet. Embedded UI with no build step matches PRODUCT.md. Weakness: Mini's supervised deployment lives outside the repository (#89).
Boundaries and dependency direction7Collectors are separate internal packages (t3, usage, sessions, herdr, hermes, projects, pmd) with deadcode clean. internal/usage/usage.go (1,069 lines) mixes several providers, and hotspots reach complexity 49 (t3 Poll) and 46 (parseClaudeWindows).
State, data, and contracts7The /api/fleet contract and pmd ingest contract are documented, and the ingest port is tested field by field against the pinned Python reference. Agent-to-server payloads have no version field; older agents are recognised by ID-namespace heuristics (README).
Changeability and testability783.5% statement coverage, fakes for HTTP and CLIs, 3-OS CI. Large functions and renderer tests that slice index.html by text markers make some changes costly (#88).
Resilience and operability7Fail-closed parsing, per-collector errors, stale labels, cooldowns and deadlines. No authentication (documented v1, tailnet only), and no resource-growth control or versioned deployment (#89, #91).

Recommendations

  1. Split the largest collector functions behind the coverage and CRAP gate in #88: start with (*Collector).Poll and parseClaudeWindows, then provider-specific parts of usage.go. Validate with unchanged golden tests; roll back by reverting the PR.
  2. Version the Linux deployment units and rollback steps (#89). Low effort, no runtime change.
  3. Add a version field to agent payloads when the next contract change lands, so the server stops inferring capabilities from ID shapes. Optional; no current defect.
  4. Keep the single-binary design. Splitting services or adding a database would add cost with no measured benefit at five machines.

Tech-stack evaluation

Recommendations

  1. Stay on Go and the current design. Keep following Go patch releases; go1.27.3 is current.
  2. Enable CodeQL for Go, JavaScript, Python and Actions (#87). It is free for public repositories and needs no code change.
  3. Pin the Node.js version used by the renderer tests with actions/setup-node to a supported LTS line (Node 24 or 26 per nodejs.org), so test behavior does not change when runner images move. Low effort.
  4. Take modernc.org/sqlite v1.61.1 through the normal Dependabot flow; no reachable advisory makes it urgent.
